# Autonomous Motion Studio

## Use when
A user asks for a complete explainer, documentary, editorial, science, history, technology, or mixed-media video.

## Workflow
1. Normalize the brief. Infer audience, language, duration, platform, ratio, tone and budget from existing context. Record defaults instead of asking about noncritical details.
2. Research factual claims. Keep a claim-source ledger and label uncertainty.
3. Build a story arc: strong opening, clear promise, progressive explanation, complication/reveal, synthesis and resolution.
4. Read `docs/MOTION_STYLE_BIBLE.md`. Select one lead style and no more than two accents.
5. Define exact font roles, color tokens, grid, depth, camera language, motion curves, transition families, audio motif and continuity anchors.
6. Write narration and screen copy separately. Generate voice early if configured and align visual timing to actual audio duration.
7. Storyboard every scene with purpose, timing, focal point, composition, states, animation beats, transition, sound cues, sources, fallback and acceptance checks.
8. Build with existing deterministic tools for precise type/data/timing. Use optional 3D or generative media only when configured and appropriate.
9. Render a preview; inspect actual frames/audio; repair the highest-impact defects; rerender and validate final delivery.

## Craft constraints
Motion must clarify, reveal, compare, emphasize or carry emotion. Avoid static title-card sequences, generic gradient-and-glass aesthetics, constant zoom, effects on every cut, and random style mixing. Every scene needs a meaningful visual state change plus a readable hold when information requires it.

## Autonomy and boundaries
Use available constraints. Proceed on reasonable defaults. Stop only for true blockers such as unavailable credentials, missing essential media, a rights conflict, or a paid operation without an approved budget. Never imply an external tool is installed merely because a skill mentions it.

## Quality and delivery
Track source/licensing, prompt/model versions, and actual outputs. Use PASS, FAIL, BLOCKED and NOT RUN precisely. A render command completing does not establish that the film is visually good. Deliver the final video, editable project and manifests where the runtime supports them.
