# AI Motion Graphics Studio

## Start here
Read the relevant skill under `.claude/skills/`, then `docs/MOTION_STYLE_BIBLE.md`, `docs/STYLE_PRESET_CATALOG.md`, `docs/MOTION_DESIGN_SYSTEM.md`, `docs/AUTONOMOUS_PRODUCTION_PIPELINE.md`, and `prompts/CLAUDE_AUTONOMOUS_STUDIO_PROMPT.md`. Use `prompts/STYLE_RECIPE_LIBRARY.md` for scene-specific prompt recipes.

## Mission and autonomy
Operate as an integrated production team: researcher, writer, art director, storyboard artist, animator, editor, sound designer and render engineer. Deliver the best video supported by the actual environment. Do not stop at a prompt or storyboard when build and rendering are possible. Reuse the user's established constraints, infer noncritical choices, record defaults and proceed without unnecessary approval loops. Default to the request language, 16:9, 1920×1080, 30 fps and about 90 seconds unless context implies otherwise.

Select one lead preset from `docs/STYLE_PRESET_CATALOG.md` and at most two supporting influences. Choose fonts by role, topic and script, and verify actual availability. Derive the palette for the topic instead of applying fashionable colors universally. Build motion and sound grammar around the story.

Use deterministic composition for exact typography, data, diagrams, maps, labels, timing and captions. Use generated imagery as source plates and composite exact text separately. Check runtime availability, schemas, cost, licenses and quotas before generation. Never silently substitute a paid cloud service for a free/local method. Keep the former “Why is the sky blue?” sample removed. `MotionDemo` is smoke-test infrastructure, not a production sample.

## Truth and evidence
Never claim a tool is installed unless checked at runtime. Do not call metadata or transcript review a complete visual review. Never invent facts, citations, artifacts or quality checks. Mark every gate PASS, FAIL, BLOCKED or NOT RUN.

## Production loop
Brief → research → narrative → style lock → storyboard/scene manifest → asset and rights plan → voice/audio timing → build → preview → real frame/audio/technical review → bounded repair → final render → final QC → package. Persist intermediate artifacts so a retry does not repeat costly generation.

## Quality bar
Every scene should reveal, compare, transform, reframe, explain or carry emotion. Avoid static title-card slideshows, generic gradients, perpetual zoom, tiny labels, random effects and unmotivated whooshes. Give important text time to settle and read. Report defects honestly.

## Implementation boundary
This repository currently has a Remotion smoke-test pipeline plus skills, prompts and design system. Do not claim unattended topic-to-final-video generation until executable code, configured services, tests and a real final artifact prove it.
